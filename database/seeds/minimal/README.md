# ชุดข้อมูลสาธิตขนาดเล็ก — `pawhome-demo-minimal-v1`

ข้อมูลน้อย อ่านง่าย แต่คลิกสาธิตได้ครบทุกขั้นตอนของ PawHome (ผู้ใช้ · เจ้าของ · ผู้ดูแล)

ข้อมูลสมมติทั้งหมด · ใช้กับ Local / Supabase Development-Test เท่านั้น · **ห้าม Production** (มี guard หยุดเองถ้าพบข้อมูลของผู้ใช้จริง)

| ไฟล์ | ใช้ทำอะไร |
| --- | --- |
| `seed.sql` | สร้างข้อมูล (transaction เดียว · รันซ้ำได้ไม่ซ้ำ) |
| `verify.sql` | ตรวจจำนวน · 10 สถานการณ์ · สถานะน้อง · FK · RBAC (ทุกแถว `ok = true`) |
| `../../verification/verify-adoption-workflow.sql` | ตรวจกฎขั้นตอนรับเลี้ยงทั้งฐานข้อมูล |
| `cleanup.sql` | ลบเฉพาะชุดนี้ (ไม่ลบบัญชี Auth) |
| `manifest.json` | ผู้ใช้ · ช่วง id · จำนวนที่คาดหวัง |

## วิธีที่ 1: สาธิตบนเครื่อง ไม่ต้องมี Supabase (แนะนำ)

```bash
cd backend && npm run dev:demo     # Express จริง + PostgreSQL ในหน่วยความจำ + ชุดข้อมูลนี้ · http://localhost:3000/api
cd frontend && npm run dev         # VITE_API_URL=http://localhost:3000/api · /admin ใช้บัญชี mini-01
```

- เข้าสู่ระบบด้วยบัญชีด้านล่าง รหัส `123456`
  - เป็นบัญชีปลอมในโหมดสาธิตเท่านั้น (Auth จำลอง ไม่เชื่อม Supabase)
- ข้อมูลกลับเป็นค่าเริ่มต้นทุกครั้งที่เปิด `dev:demo` ใหม่

## วิธีที่ 2: Supabase Development (ต้องยืนยันว่าเป็นโปรเจกต์ทดสอบ)

1. รัน `database/schema.sql` → `migrations/001` → `002` → `003`
2. สร้างบัญชีผ่าน Admin API (ห้าม insert ลง `auth.users` ตรง):
   ```bash
   cd backend
   SEED_TARGET=development SEED_ALLOWED_PROJECT_REFS=<dev-ref> DEMO_USER_PASSWORD=<รหัสทดสอบ ≥12 ตัว> npm run seed:demo-users -- --dataset minimal
   ```
3. SQL Editor → รัน `seed.sql` → `verify.sql` + `verify-adoption-workflow.sql`
